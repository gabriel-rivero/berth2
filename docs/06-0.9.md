# Berth — 0.9 (draft)

0.9 closes M4. It is a correctness-and-measurement release: fix the focus bug
daily use just filed, and finish the one M4 criterion still open — the
Instruments trace against the §9 budgets. No new product surface.

Status: draft. Scope agreed, nothing started.

## 1. Focus ownership (filed 2026-11-17)

**Report.** Two panes side by side, opencode on the left and a shell on the
right. Clicking into the left pane keeps focus for a moment, then focus returns
to the right pane. Closing the right pane works around it.

**Cause.** `GhosttySurfaceView.mouseDown` (`app/Sources/Berth/GhosttySurfaceView.swift:584`)
makes the clicked view first responder but never tells the core, so the core's
`selected_surface` / workspace `active_surface` still name the other pane. Every
reconcile pass ends with a focus correction that hands focus back to
`layout.activeSurface` (`app/Sources/Berth/BerthCoreHost.swift:436-440`), and the
next event — an opencode agent event, the one-second detection pass, a socket
call — runs that pass. The click is undone, which is exactly the "kept for a
moment" behaviour.

**Fix.**

- Report user focus to the core when a terminal takes first responder:
  `surface.activate` (`core/crates/berth-core/src/state.rs:317`). It updates the
  pane's active tab, the workspace's active surface and the selected surface,
  and its `focus` host call re-asserts the view that already has focus. Clicking
  the already-visible surface does not change `structureKey`, so this does not
  rebuild the tree.
- Make the reconcile-time correction skip when a terminal surface already has
  focus, so a stale core can never take the keyboard away from the user.

**Acceptance.**

- [ ] Clicking between two panes holds focus for 60 s of agent events and
      detection passes, with an agent running in the clicked pane.
- [ ] `berth active` names the pane that has focus.
- [ ] Quit and relaunch restores focus to the pane that had it.
- [ ] Regression test: focus a surface, run a reconcile, assert the first
      responder does not change.

## 2. Instruments trace (the last M4 criterion)

Measure the `docs/02-architecture.md` §9 budgets instead of trusting the
breadcrumbs.

**Prerequisite: met.** Xcode 27.2 (27B52) is installed, the license is accepted,
`xcode-select` points at it, and `xctrace` 27.2 lists its templates. `metal` and
XCTest are available too, so `make bootstrap` and `swift test` now work on this
Mac; `make fetch-engine` stays as the path for machines with only the Command
Line Tools.

| Budget | How | Where the number goes |
| --- | --- | --- |
| Cold start → first interactive frame (restored 3 workspaces) ≤ 150 ms | `xctrace record --template 'Time Profiler' --launch build/Berth.app`, plus the `app: launched` → `reconcile: end applied=true` gap in `berth.log` | §9 table |
| Key input → paint ≤ 1 frame, no main-thread core calls | Time Profiler while typing into a pane with 8 panes open; confirm in `berth.log` that keystrokes reach Ghostty without a `ui:` or `socket: core dispatch` line between them. `sample <pid> 10` works without Xcode for the hotspot list | §9 table |
| Socket round trip p99 ≤ 2 ms | `for i in $(seq 1 500); do berth ping; done` with per-call timing | §9 table |
| Idle CPU < 1 %, 8 panes, 1 hidden window | `powermetrics --samplers cpu_power -i 5000 -n 60` and `top -pid` | §9 table |
| RSS ≤ 1.2 GB, 8 panes × 10k scrollback | `ps -o rss= -p $(pgrep -x Berth)` after `seq 1 10000` in each pane | §9 table |

**Acceptance.** Every §9 row has a measured value and a pass/fail; anything over
budget gets either a fix in 0.9 or a named follow-up with the number attached.
The results go in the §9 table (measured column) and in this doc's release
notes.

## 3. Filed bugs

Daily use continues while 0.9 is open. Each filed bug gets a repro, a cause, a
fix and a regression test where the layer allows one. Correctness bugs land in
0.9 or a 0.9.x patch; feature requests go to the M5 list.

## 4. Out of scope

The M5 pull-forward items — group management UI, geometric focus, agent mute and
multi-agent rows, journal semantics, headless app-test mode, socket hardening —
stay for 0.10 unless a filed bug forces one in.

## Release

`0.9.0` when both acceptance lists pass. The release notes are the CHANGELOG
section for the tag, as CI already does. A focus or restore regression filed
after that ships as `0.9.x` rather than waiting for the next feature release.
